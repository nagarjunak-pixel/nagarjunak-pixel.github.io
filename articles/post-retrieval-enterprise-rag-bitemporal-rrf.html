Post-Retrieval Enterprise RAG: Bi-Temporal Memory, Pruned RRF Cascades & Cross-Page Table Stitching

Published 2026-11-27 · Nagarjuna Kamireddy

When an enterprise RAG assistant answers from an outdated policy clause, teams instinctively blame the embedding model. In practice across large-scale engineering and support deployments (including hybrid OpenSearch and 6-agent Neo4j GraphRAG workflows serving 750K+ automated requests at John Deere), retrieval recall is rarely the sole culprit. Recent benchmarks isolate what happens after the right paragraph lands in the prompt:

  • 53% Temporal Version Confusion (arXiv:2611.34762): Even with gold facts in context, 8B–27B models ignore retrieved memory 46% of the time and confuse superseded document versions 53% of the time when old and current clauses share high lexical similarity.
  • 32K Reranker Latency Bottlenecks (arXiv:2611.33844): Running cross-encoders across wide hybrid pools blows interactive p95 budgets unless pruned via coarse-to-fine Reciprocal Rank Fusion.
  • Cross-Page Table Header Loss (arXiv:2611.34420): Naive PDF page splitting severs page-2 numeric rows from their page-1 column headers.

1. Subject-Keyed Bi-Temporal Addressing (llm-knowledge-base v1.1.0)

In llm-knowledge-base (app/temporal_addressing.py), every compiled policy or specification clause carries a deterministic lifecycle tuple (clause_id, subject_key, valid_from, valid_to, superseded_by). Prior to prompt assembly, SubjectTemporalIndex resolves active versus superseded clauses at query_date, tags retired versions inline as SUPERSEDED_BY, and runs a post-generation verify_citations gate that blocks both superseded citations and planted fake statutory identifiers.

2. Three-Stage Pruned Reciprocal Rank Fusion (vecta)

To preserve exact part-number and SKU precision alongside semantic recall, vecta combines Okapi BM25 with filtered HNSW/IVF-PQ dense search via Reciprocal Rank Fusion (1 / (60 + rank)). Pruning fused candidates at the 80th-percentile cutoff before cross-encoder scoring captures +4.02 to +9.43 percentage points on 32K long-context benchmarks at 1.88x faster pruning speed, paired with calibrated low-confidence abstention in enterprise-helpdesk-rag-guardrails.

3. Zero-Extra-Token Cross-Page Seam Stitching

Rather than re-OCR-ing entire PDFs through expensive vision tokens, stitch_cross_page_seams inspects trailing table headers on page p and leading pipe-delimited rows on page p+1, propagating column headers and 3-line footnote context deterministically across page breaks.
